# AI Support Copilot — Product Overview

## 1) Что это за продукт и какую боль закрывает
AI Support Copilot — “второй пилот” для агента поддержки (не заменяет человека в начале), который:
- быстро понимает кейс (суммаризация и timeline)
- классифицирует запрос (intent) и извлекает ключевые факты
- находит правильные политики/правила (RAG по knowledge base)
- предлагает следующий шаг (next-best-action)
- генерирует черновик ответа в нужном тоне/языке
- помогает эскалировать (если риск/исключение)

Почему это ценность для большой travel-компании:
- огромный объём обращений (стоимость поддержки высокая)
- кейсы повторяются (refund/change dates/payment issues и т.п.)
- ошибки/неправильные обещания = деньги и комплаенс-риски
- нужно быстрее (SLA) и одинаково качественно (стандарты)

## 2) Для кого и где это живёт
**Основной пользователь:** агент саппорта (L1/L2), тимлид, QA, тренинг.  
**Где встроено:** прямо в интерфейс тикетов (Zendesk / Salesforce Service Cloud / внутренний тул).  
Copilot — панель справа или “карточка”, которая обновляется при открытии тикета.

## 3) Сценарии использования (Use Cases)
**UC1. Суммаризация тикета в 10 секунд**
- выжимка диалога: что случилось, даты, сумма, статус брони, что уже пробовали
- короткий timeline действий (со ссылками на сообщения)

**UC2. Определи тип проблемы (intent) + извлеки факты**
- intent: refund / cancellation / change dates / payment / overbooking / no-show / ID verification / scam suspicion / accessibility / special requests
- факты: booking_id, даты, сумма, валюта, объект, тариф, политика отмены, кто пишет (guest/host)

**UC3. Найди политику и процитируй**
- Copilot обязан дать источники: help center, SOP, правила компенсаций
- “почему так” + ссылка на документ (чтобы агент доверял)

**UC4. Сгенерируй черновик ответа**
- тон: дружелюбно-деловой, без юридических рисков
- язык: EN/HE/RU (или авто-детект и перевод)
- вставляет персональные факты (даты/сумма) только если подтверждены

**UC5. Next Best Action**
- 1–3 шага: запросить документ, проверить статус платежа, предложить альтернативу, эскалировать, открыть расследование
- встроенные “кнопки”: “Apply template”, “Escalate”, “Request info”

**UC6. Флажки риска**
- подозрение на мошенничество в переписке
- кейс требует исключения из политики
- возможный chargeback / legal risk
- раздражение клиента (sentiment) → мягкий тон и ускорение

## 4) Чёткие требования к продукту
**Functional requirements**
- автосуммаризация и факт-экстракция
- intent classification + confidence score
- поиск по базе знаний (RAG)
- генерация ответа с “политикой в руках”
- шаблоны + редактирование человеком
- логирование: что предложил Copilot и что принял агент

**Non-functional requirements (важно для enterprise)**
- точность > креативность (лучше “не знаю” чем галлюцинация)
- latency: 2–6 сек на полный пакет
- отказоустойчивость: fallback на шаблоны
- приватность/PII: маскирование, контроль доступа
- многоязычность

## 5) Данные и источники знаний
**A) Ticket data (операционные данные)**
- текст чата/писем, attachments и метаданные
- поля брони: даты, объект, цена, тариф, статус
- исход кейса: решено/эскалировано, компенсация, причина
- SLA/время обработки/CSAT

**B) Knowledge base (то, что будет в RAG)**
- политики отмены/компенсаций
- SOP для агентов
- шаблоны ответов
- правила комплаенса/юридические фразы
- списки allowed/forbidden claims (что нельзя обещать)

Ключевой момент: Copilot работает только с “истиной” из KB.

## 6) Архитектура системы (как это устроено)
**Ticket Ingestor**
- получает тикет и данные брони (из CRM/Support system)
- чистит HTML, нормализует формат, убирает мусор

**PII/Compliance Guard**
- маскирует чувствительные данные при необходимости
- определяет, что можно отправлять в модель

**NLU Layer (понимание)**
- intent classifier
- entity extraction (даты, суммы, booking_id, объект, причина)

**RAG Retrieval**
- поиск релевантных документов в KB
- hybrid search: keyword + embeddings
- reranker (пересортировка результатов)

**LLM Orchestrator (генерация)**
- summary, next steps, draft reply
- строгий “grounded” режим по источникам
- цитаты/ссылки + уровень уверенности

**Agent UI + Feedback Loop**
- агент видит рекомендации, редактирует, подтверждает
- клики и правки идут в аналитику и обучение

## 7) ML/AI компоненты (что моделируем)
**7.1 Intent Classification**
- цель: маршрутизация и правильные политики
- модель: LogReg / XGBoost / маленький transformer
- вход: текст + метаданные (страна, тип объекта, канал)
- выход: intent + confidence

**7.2 Entity / Fact Extraction**
- NER/RegEx + LLM-extractor с валидаторами
- обязательная проверка: дата в будущем? сумма совпадает с booking record?

**7.3 Summarization**
- короткая выжимка + timeline
- без домыслов, только факты из тикета

**7.4 RAG**
- индексация KB: чанки 300–800 токенов, метаданные (страна, продукт, тариф, дата)
- поиск: embeddings + keyword
- rerank: топ-k самых точных
- генерация: ответ с опорой на документы X,Y,Z

**7.5 Next-Best-Action**
- на старте: правила + intent
- позже: модель, обученная на успешных решениях

**7.6 Tone & Translation**
- авто-детект языка
- перевод черновика с сохранением смысла и политики
- нейтрально-профессиональный тон

## 8) Guardrails: как не “влететь” на галлюцинациях
- Answer must cite sources (нет источника → “нужно уточнение/эскалация”)
- Allowed claims list (что можно говорить)
- Forbidden claims list (что нельзя обещать)
- шаблоны: “According to the policy…”
- проверки фактов: суммы/даты/статусы только из систем записи
- отдельный режим для high-risk кейсов (fraud/legal)

## 9) Как измерять успех (KPI)
**Операционные метрики**
- AHT ↓
- Time to first response ↓
- Escalation rate ↓ (или “правильная эскалация” ↑)
- First Contact Resolution ↑

**Качество**
- CSAT ↑
- acceptance rate (доля принятых рекомендаций)
- доля правок агента (меньше правок = лучше)

**Безопасность/риски**
- число нарушений политики ~ 0
- hallucination rate (ответ без источников)
- доля неверных обещаний

## 10) MVP план (2–3 недели)
**Цель:** доказать ценность на 1–2 самых частых интентах.

**MVP Scope**
- интенты: cancellation/refund + change dates
- функции:
  - summary + timeline
  - intent classification
  - RAG по политикам
  - draft reply (с источниками)
  - feedback: use / edit / reject

**Что показать в демо**
- открываешь тикет → через 3 сек готов summary + policy excerpts + draft reply
- агент правит 1–2 строки и отправляет
- логируется результат

## 11) Roadmap до “как у большой компании”
**Phase 2 (4–8 недель)**
- добавить 5–10 интентов
- sentiment + priority
- умная эскалация (fraud/legal)
- обучение на feedback

**Phase 3 (2–3 месяца)**
- next-best-action как рекомендатель
- аналитика причин обращений (insight mining)
- авто-улучшение KB (suggestions)

**Phase 4 (enterprise)**
- multi-tenant / RBAC / audit logs
- evaluation harness + регресс-тесты промптов
- мониторинг дрейфа и качества ответов

## 12) Главные риски и как их закрыть
- Галлюцинации → обязательные источники + “no-answer”
- Неправильные обещания → allowed/forbidden + шаблоны
- Старые политики → versioning KB + “last updated”
- PII/данные клиентов → маскирование + доступы + лог-редакция
- Сопротивление агентов → “Copilot”, не “автомат”; демонстрация экономии времени
